## 1. プロジェクトの目的

| 項目 | 内容 |
|------|------|
| 目的（1文） | AiNA MyPage に掲載されている**行事・イベントの予定**を定期的に取得し、追加・変更・削除を検知して Google カレンダーに反映する。 |
| 背景・課題 | スケジュールはサイト上に記載されているが、サイトを確認して Google カレンダーに手動で登録することが不便。**システムに確認と更新を任せたい**。 |
| 達成したい状態（ゴール） | サーバ上で定期実行され、指定間隔でサイトと Google カレンダーを確認し、差分だけを**パッチ形式**で Google カレンダーに反映される状態。 |

## 2. ユーザーと利用シーン

（ヒアリング: 主に使う人は自分、人数は自分、利用端末は **PC のみ**）

| ユーザー種別 | 説明 | 主な利用シーン |
|--------------|------|----------------|
| 利用者（自分） | システムの設定・運用と、Google カレンダーの参照。**利用端末は PC のみ**。 | サーバ設定・認証情報の管理。Google カレンダーでスケジュールを閲覧。**更新はシステム（スクレイピングや API）が行い、自分は確認するだけ**。 |
| カレンダー閲覧者 | 当該 Google カレンダーを共有されている人 | 共有されたカレンダーでイベントを閲覧（編集は自分のみ、表示はアクセス可能な全員）。 |

## 3. 機能要件

（ヒアリング: 指定URLのイベントをサイトから確認し、追加・削除・満員になったら Google カレンダーに新規追加・削除・更新。毎日 or 1時間に1回、間隔は設定で変更可能。絶対に必要＝前回比較→差分で Google カレンダー更新、パッチ形式、指定間隔で確認、サーバで定期実行。あると嬉しい＝間隔を簡単に変更できること。）

### 3.1 必須機能（Must）

| No. | 機能名 | 概要 | 備考 |
|-----|--------|------|------|
| M1 | 掲載スケジュールの取得 | AiNA MyPage（要ログイン）から **compass** と **live-course** の2URLのスケジュールを取得する | フォームログイン（ID・パスワード）後、指定URLを取得。認証情報は環境変数（.env）で管理。 |
| M2 | 前回との比較と差分検知 | 今回の取得結果と**前回の更新内容**を比較し、**追加・変更・削除**を検知する | パッチ形式（変更分だけを扱う）。初回は全件、2回目以降は差分比較を想定。 |
| M3 | Google カレンダーへの反映 | 検知した追加・変更・削除を Google カレンダーに反映する（新規追加、更新、削除） | 反映先カレンダーIDは設定で指定。「満員」の扱いは要確認（例：タイトルや説明文に「満員」を付与等）。 |
| M4 | 定期実行 | **指定した間隔**（例：1時間毎・5分毎・毎日）でサーバ上で実行する | ローカルではなくサーバにデプロイし、Cron 等で定期実行。間隔は設定で変更可能にすること。 |

### 3.2 任意機能（Want）

| No. | 機能名 | 概要 | 備考 |
|-----|--------|------|------|
| W1 | 間隔の簡単な変更 | パッチ形式の実行間隔を、設定ファイルや簡易UIで簡単に変更できるようにする | ヒアリング「あると嬉しい」に対応。 |

## 4. 非機能要件

（ヒアリング: 利用者1人・PC のみ。認証は .env で管理。サーバで定期実行。）

| 分類 | 項目 | 内容（要確認の場合はその旨を記載） |
|------|------|-----------------------------------|
| 性能 | 同時利用者数・想定件数 | 利用者1人。想定イベント件数は要確認。 |
| 利用環境 | 端末 | **PC のみ**（ヒアリングで回答）。 |
| セキュリティ | 認証情報の管理 | AiNA MyPage の ID/パスワード、Google カレンダー用トークン等は **環境変数（.env）で管理し、Git にコミットしない**。 |
| セキュリティ | データの取り扱い | 取得したスケジュールは Google カレンダーに書き込む。個人情報の扱いは要確認。 |
| 運用 | 実行環境 | **サーバにデプロイ**し、Cron 等で定期実行（ローカル実行は対象外）。Vercel Cron や常時稼働サーバ等を想定。 |
| その他 | 参照元・登録先 | **参照元**: AiNA MyPage。ログインURL: https://mypage.ai-na.co.jp/login。取得URL: /user/compass, /user/live-course。**登録先**: Google カレンダー。 |

## 5. 用語集

プロジェクト内で意味を揃えて使う用語です。**ヒアリングシート「5. 用語のメモ」に基づく**。

| 用語 | 定義 |
|------|------|
| 掲載スケジュール | **特定サイト（本プロジェクトでは AiNA MyPage）に掲載されているイベントのこと**。compass / live-course の2URLで提供。 |
| 登録スケジュール | **Google カレンダーに登録したイベントのこと**。利用者は Google カレンダー（または共有されたカレンダー）で参照する。 |
| 更新 | **日付や内容を書き換えること**。本システムでは「掲載スケジュールの追加・変更・削除を検知し、Google カレンダーに同様の変更を反映する」ことを指す。 |
| AiNA MyPage | 参照元サイト。ログインURL: https://mypage.ai-na.co.jp/login。取得対象: /user/compass, /user/live-course。フォームログイン。 |

## 検討・提案メモ

（ヒアリングシート「検討・提案メモ」に基づく。）

- **確認済み**: 参照元は AiNA MyPage（フォームログイン、ログインURL・compass / live-course の2URL）。登録先は Google カレンダー。利用者1人・PC のみ。更新はシステムが実行、間隔は設定で変更可能。
- **まだ確認したいこと（ヒアリングより）**: 取得間隔の**最小・最大・デフォルト値**。「満員」になった場合の Google カレンダー上の表示仕様（タイトルに「満員」を付ける等）。**AiNA MyPage の利用規約**（スクレイピング・自動取得の可否）。
- **提案（ヒアリングより）**: 間隔は設定ファイルまたは管理画面で変更できるようにする。参照元が API を提供している場合は API 利用を優先。初回は全件同期、2回目以降は前回結果との差分だけ比較。サーバは Vercel Cron や常時稼働の小型サーバ等を想定。
- **リスク・懸念**: 参照元の画面変更で取得処理が動かなくなる可能性。認証情報は必ず .env で管理し、リポジトリに含めないこと。
- **セキュリティ注意**: ログイン用 ID/パスワードはコードやドキュメントに記載せず、.env のみで保持する。チャットで共有した場合は、必要に応じてパスワードの変更を検討すること。

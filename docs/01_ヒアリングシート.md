# ヒアリングシート（作りたいことの言語化）

お客様と一緒に「何をしたいか」を整理するためのシートです。  
気楽に、思いついたことや困っていることを書いてください。正解はありません。

---

## 1. だれが使いますか？

| 質問 | 記入欄・選択 |
|------|--------------|
| 主に使う人は？（例：自分、チームの仲間、お客様） | 自分 |
| 人数のイメージは？（例：自分だけ / 数人 / 数十人） | 自分 |
| パソコン・スマホ・タブレットのどれで使いたい？ | □ PC のみ |

## 2. 何の「スケジュール」を扱いますか？

| 質問 | 記入欄・選択 |
|------|--------------|
| スケジュールの種類は？（例に近いものを選ぶか、自分で書いても可） | □ 行事・イベントの予定 |
| 今は何で管理している？（例：手書き、Excel、紙のカレンダー、別のシステム） | スケジュールはサイト上に記載されている。登録先は Google カレンダー |
| そこで困っていること・不便なことは？ | サイトを確認して、Google カレンダーに手動で登録することが不便。 |

## 3. 「更新」で何をしたいですか？

| 質問 | 記入欄 |
|------|--------|
| やりたいことの具体例を 1 つ書いてください。（例：「毎週月曜に来週のシフトを入れて、みんなに共有したい」） | 指定URLに記載されているイベントのスケジュールを逐一サイトから確認して、スケジュールが追加もしくは削除、満員になったら Google カレンダーに新規追加、削除、更新をしてほしい |
| 誰が更新して、誰が見るイメージですか？ | スクレイピングやAPIを使ってすべてシステムが確認と更新をしてほしい |
| 更新のタイミングは？（例：随時、毎日、毎週〇曜日） | 毎日、もしくは１時間に一回（更新タイミングの間隔は設定により変更できること） |

## 4. 絶対に外せないこと・あると嬉しいこと

| 種類 | 内容（思いつくままでOK） |
|------|--------------------------|
| 絶対に必要 | ・サイト（要ログイン）にあるスケジュールを逐一確認して、前回の更新内容と比較したところ、追加、変更、削除のいずれかがされたら Google カレンダーにスケジュールを更新すること。・できる限りパッチ形式で、指定した間隔（1時間毎とか5分毎とか）でサイトと Google カレンダーの確認をする。・ローカルではなくサーバーにあげて定期的にシステムが実行されるような仕組みにしてほしい |
| あると嬉しい | パッチ形式の間隔を簡単に変更できること |

## 検討・提案メモ

- **ヒアリングで分かったことの要約**
  - **利用者**: 自分1人、PC のみ。
  - **対象**: 特定サイトに掲載されている**行事・イベントの予定**。参照先は「要ログイン」のサイト。
  - **やりたいこと**: そのサイトの掲載スケジュールを定期的に確認し、**追加・変更・削除**があれば **Google カレンダー**に同じ内容で反映する。比較は「前回の更新内容」と差分で行い、**パッチ形式**（変更分だけ）で、**指定間隔（例：1時間毎・5分毎）**でサイトと Google カレンダーを確認する。**サーバ上で定期実行**する仕組みにする。
  - **絶対に必要**: ログインが必要なサイトの取得、前回との比較、Google カレンダーへの反映、間隔の設定、サーバでの定期実行。
  - **あると嬉しい**: 間隔の変更を簡単にできること。
  - **用語**: 掲載スケジュール＝サイト上のイベント、登録スケジュール＝Google カレンダー上のイベント、更新＝追加・変更・削除の反映。

- **確認済み（参照元・登録先）**
  - **参照元サイト（AiNA MyPage）**
    - ログインURL: `https://mypage.ai-na.co.jp/login`
    - ログイン方式: **フォームログイン**（ID・パスワード）
    - 認証情報: **環境変数（.env）で管理すること。リポジトリにコミットしない。**
    - 取得スケジュールURL（2種）:
      - `https://mypage.ai-na.co.jp/user/compass`
      - `https://mypage.ai-na.co.jp/user/live-course`
  - **登録先**: **Google カレンダー**。システムは取得したスケジュールの差分を Google カレンダーに追加・更新・削除する。

- **まだ確認したいこと・前提として決めたいこと**
  - **間隔**: 最小・最大の希望（例：5分〜24時間）とデフォルト値。
  - **「満員」の扱い**: 満員になったら Google カレンダー上のイベントをどう更新するか（例：タイトルに「満員」を付ける、説明文を変える等）。
  - **利用規約**: AiNA MyPage のスクレイピング・自動取得の可否を利用規約で確認すること。

- **提案（別のやり方・追加で検討すると良さそうなこと）**
  - 間隔は設定ファイルまたは管理画面で変更できるようにすると、運用しやすい。
  - 参照元が API を提供している場合は API 利用を優先すると、規約・保守の面で有利なことが多い。
  - 初回は「全件同期」、2回目以降は「前回結果との差分だけ」で比較する方式にすると、パッチ形式と整合する。
  - サーバは Vercel Cron や常時稼働する小型サーバなど、定期実行ができる環境を想定するとよい。
